# Module acceptance obligations

This is a test-work register, not a completion checklist. Original facts come from the matching controllers/repositories, MODEL-RULES.md and the schema dictionary. "Existing tests" below means relevant current regression code was executed; it does not prove original equivalence. All CRUD includes validation failure, role denial, record ownership, stale/concurrent changes where applicable, reload and print/export when present.

| Module family | Source workflow/rules to verify | Current evidence / blocking difference | Remaining acceptance |
| --- | --- | --- | --- |
| Identity and users | User plus role-owner row; role middleware and request authorization; active/inactive state; password/profile/MFA/language | Existing auth/HTTP/staff tests; nine-role authenticated probes; CMS permission advertisement discrepancy | Nine populated workspaces; editable role/permission policy; create/update/deactivate user; stale sessions; invitation/reset/MFA UI |
| Dashboard | Role-specific aggregates and owned records; correct billing sources/date intervals | Overview scope/ready-bed regression passed; page probe | Reconcile every metric/chart against its original business meaning; no demo fallback |
| Smart-card templates/cards | Unique template name/color; six toggles; all/single/unassigned generation; template delete clears references | Browser proves session-only persistence; separate current token-card API | Full template CRUD/generation plus DB and cross-context reload/print/QR |
| Appointments/calendar | Patient/doctor/department/date required; doctor timetable, available slots, booking status and payment/custom fields | Existing scheduling/idempotency/overlap tests; catalog page probes | Exact form fields, doctor charge, calendar actions, cancellation/status rules and patient self-booking journey |
| Queues | Appointment FK, queue number/display order and doctor/date context | Existing queue regression; page probe | Operator transitions, public display privacy, original theme/config and concurrent numbering |
| Attendance | Not in ZIP; reference is newer demo with shifts/assignments/reports/leaves/corrections | Existing attendance regression/default-shift tests; staff-vs-patient shift-list probes | Live-reference field contracts; every non-shift tab; leave/correction approvals; actual frontend persistence |

Every row needs action-specific evidence before it can be called fully verified. Source excerpts make those actions discoverable; they do not substitute for populated role/CRUD/print tests. Current regressions that pass remain useful and should be retained while filling these gaps.
